# 유니 스킬: terms

Oct 9, 2026 · @astrove

츄니즘 용어와 은어의 뜻을 설명하는 스킬이다. 용어 데이터는 `terms` 서비스에 있고, 랭크·난이도·램프·점수처럼 값이 되는 용어는 이 스킬이 아니라 코어의 표준 인자 타입이 해석한다. 그래서 이 스킬을 꺼도 다른 스킬은 "트플플"을 그대로 알아듣는다.

## 개요

```yaml
name: terms
description: 츄니즘 용어와 은어(트플플, 이론치, 오버파워, 비비기 등)의 뜻을 설명하고, 서버에서 쓰는 은어를 등록한다.
examples:
  - 오버파워가 뭐야?
  - 트플플이 몇 점부터야?
  - 비비기가 뭐야?
category: 질문 답변
game: chunithm
version: 1
services: [terms, players, notify, settings]
```

태그 조건은 없다. 서버 은어 등록을 끄거나 되돌리는 도구만 `admin`이 필요하다.

## 용어의 두 종류

| 종류 | 예 | 해석하는 곳 | 추가 방법 |
| --- | --- | --- | --- |
| 값 용어 | 랭크, 난이도, 램프, 점수 표현 | 코어의 `RankRef`, `DifficultyRef`, `LampRef`, `ScoreRef` | `terms.yaml` 수정으로만. 잘못 들어가면 계산이 틀어지기 때문이다 |
| 개념 용어 | 오버파워, 상수, 저스티스 크리티컬, 비비기(안미츠), 판정 A·B, 베스트 프레임 | 이 스킬 | `terms.yaml`, 또는 서버에서 제안하고 `admin`이 승인 |

**값 용어의 해석 (코어 표준 타입)**

- 모델은 "트플플", "마스", "이론치", "1007.5k"처럼 들은 말을 그대로 넘기고, 코어가 `terms` 서비스로 정식 값(SSS+ → 1,009,000 등)으로 바꿔 함수에 넘긴다.
- 모르는 말이면 함수는 불리지 않고 "후보: SSS+, SSS" 같은 오류가 모델에 돌아간다. 모델이 점수 기준을 기억으로 판단하지 않는다.
- 점수 표현은 "1007.5k", "100만 7천5백", "1,007,500"을 모두 같은 값으로 읽는다.

## 용어 항목의 형식

| 칸 | 내용 |
| --- | --- |
| 정식 표기 | 예: SSS+ |
| 분류 | 랭크, 난이도, 램프, 점수, 판정, 개념, 기술 |
| 별칭 | 한국어, 일본어, 영어 별칭 목록 |
| 값 | 값 용어만. 예: 1,009,000 |
| 뜻 | 한두 문장 |
| 출처 | 확인한 링크. 없으면 "서버 사용"으로 표시 |
| 범위 | 전역(`terms.yaml`) 또는 서버 |

**항목 예시** (형식을 보여 주기 위한 것이다. 실제 목록은 플레이어들이 쓰는 말을 모아 확인한 뒤 넣는다)

```yaml
- canonical: SSS+
  category: rank
  aliases: [트플플]
  value: 1009000
  meaning: 1,009,000점 이상. 최고 랭크.
- canonical: SSS
  category: rank
  aliases: [트리플]
  value: 1007500
- canonical: AJC
  category: lamp
  aliases: [이론치]
  value: 1010000
  meaning: 모든 노트를 저스티스 크리티컬로 친 만점.
- canonical: 안미츠
  category: technique
  aliases: [비비기]
  meaning: 타이밍이 조금 다른 두 노트를 동시에 쳐서 저스티스 크리티컬 판정 안에 넣는 기술.
```

## 서버 은어

- 플레이어는 `/용어 제안`이나 유니에게 말로 개념 용어를 제안할 수 있다. 신고제라 승인을 기다리지 않고 바로 반영되고, admin의 "보고 채널"(`admin` 스킬 설정)이 있으면 거기로 알린다. `admin`은 나중에 부적절한 등록을 끄거나 되돌릴 수 있다(구현 결정 참고).
- 난이도·랭크·램프·작곡가의 말을 못 알아들으면, 모델이 비슷한 것을 짐작해 맞는지 되묻고 확인받은 뒤 `alias_add`로 별칭을 저장한다(2026-10-21 사용자 결정). 별칭은 봇 전역이고(서버별이 아니다), 저장하면 `RankRef`·`DifficultyRef`·`LampRef`·작곡가 검색이 다음부터 묻지 않고 알아듣는다. 정식 이름(`terms.yaml`)과 값은 그대로이고, 이미 다른 뜻으로 쓰이는 말은 저장하지 않는다(전에는 "서버에서 값 용어의 별칭을 추가할 수 없다"였다).
- 서버 은어는 그 서버에서만 쓴다. 전역 용어와 충돌하면 전역 용어가 이긴다.

## 다른 스킬과의 관계

- **web-qa**: 용어 사전에 있는 말은 웹 검색 없이 이 스킬로 답한다. 없는 말만 `web-qa`로 넘어간다. 검색으로 찾은 뜻은 서버 용어 제안으로 남길 수 있다.
- **표기**: 표시물(임베드·표)은 항상 정식 표기를 쓴다. 유니의 말은 플레이어가 쓴 표현을 따라갈 수 있다. 예: "트플플까지 3.20어택이에요."

## 도구

| 함수 | 하는 일 | 인자 | 슬래시 | 태그 | display | confirm |
| --- | --- | --- | --- | --- | --- | --- |
| `explain` | 용어의 뜻, 별칭, 값, 출처 | `term` | `/용어 뜻` | 없음 | optional | never |
| `list` | 분류별 용어 목록 (표 반환) | `category`(선택) | `/용어 목록` | 없음 | 표 | never |
| `suggest` | 서버 은어 등록(즉시 반영) | `term`, `meaning`, `aliases` | `/용어 제안` | 없음 | optional | never |
| `review` | 등록 끄기·되돌리기 | 제안 id, 켤지 | `/용어 반영여부` | `admin` | optional | always |
| `alias_add` | 확인받은 난이도·랭크·램프·작곡가 별칭 저장(전역) | `kind`(난이도·랭크·램프·작곡가), `alias`, `canonical` | `/용어 별칭 추가` | 없음 | optional | never |
| `alias_remove` | 저장된 별칭 삭제(추가한 사람과 admin만) | `kind`, `alias` | `/용어 별칭 삭제` | 없음 | optional | never |

## 이벤트

내거나 받는 이벤트는 없다.

## 데이터

| 위치 | 내용 |
| --- | --- |
| `services/chunithm/data/terms.yaml` | 전역 용어(값 용어와 개념 용어). 저장소에서 검토해 고친다 |
| `terms_aliases` 테이블 (`migrations/core/021_terms_aliases.sql`) | 종류(difficulty·rank·lamp·artist), 별칭, 정식 이름, 등록한 플레이어, 시각. 전역. 부팅 때 `load_aliases()`가 난이도·랭크·램프 별칭 지도에 섞어 넣어 해석 경로는 그대로다 |
| `terms_server` 테이블 (`terms` 서비스 소유, `migrations/core/`에서 만든다) | 서버, 용어, 뜻, 별칭, 등록한 플레이어, 상태(approved·rejected, 기본 approved), 반영여부를 바꾼 플레이어 |

## 유니 지침 (SKILL.md 본문 초안)

- 용어 뜻은 사전에 있는 내용만 말한다. 사전에 없으면 `web-qa`를 펼친다.
- 랭크·램프의 점수 기준은 도구 결과의 값만 쓴다.
- 서버 은어를 설명할 때는 이 서버에서 쓰는 말이라고 밝힌다.
- 플레이어가 모르는 은어를 써서 해석에 실패하면, 뜻을 물어보고 용어 제안을 권할 수 있다.

## 테스트

- 별칭이 같은 정식 값으로 풀리는지(`RankRef`, `LampRef` 등).
- 점수 표현 여러 형식의 해석.
- 저장한 별칭이 다음 해석에 쓰이는지, 이미 다른 뜻인 말은 거절하는지.
- 등록이 바로 해석과 설명에 쓰이는지, admin이 끄면 안 쓰이는지.
- 서버 용어가 다른 서버에서 보이지 않는지.

## 구현 결정 (2026-10-18, 실기에서 받은 요청)

- 서버 은어 등록을 허가제(admin 승인 전까지 비공개)에서 신고제(즉시 반영 + admin 보고 채널에 알림)로 바꿨다. 이유: 은어 하나 등록하는 데마다 admin을 기다려야 하는 게 체감 마찰이 크고, 잘못 등록된 것은 사후에 꺼도 충분하다는 판단.
- `admin` 스킬에 서버별 "보고 채널" 설정(`/관리 보고채널`)을 추가했다 — 비어 있으면 아무 데도 안 보낸다. 이 채널은 서버 은어 외에 앞으로 다른 admin 사후 검토 보고에도 재사용할 수 있다.
- `review()`는 "한 번만 심사"에서 "껐다 켰다 하는 토글"로 바뀌었다 — 되돌리기도 가능하다.

## 미확인 사항

- 초기 용어 목록. 한국 커뮤니티 용어를 정리한 출처를 검색으로 찾지 못했다. 플레이어들이 실제로 쓰는 말을 먼저 모으고, 확인한 것만 넣는다.
