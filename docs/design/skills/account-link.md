# 유니 스킬: account-link

Oct 9, 2026 · @astrove

한 사람이 쓰는 디스코드 계정 여러 개를 플레이어 하나로 묶는 스킬이다. 묶인 계정은 어느 쪽으로 유니를 불러도 같은 CHUNITHM-NET 연결, 기록, 목표, 세션, 메모리, 태그를 쓴다. 연결과 해제는 슬래시 명령과 버튼으로만 하고, LLM 도구는 두지 않는다.

## 개요

```yaml
name: account-link
description: 디스코드 부계정을 한 플레이어로 연결하는 방법을 안내한다. 연결과 해제는 슬래시 명령으로만 한다.
examples:
  - 디코 부계정도 연결하고 싶어
  - 연결된 계정 보여 줘
category: 계정 연결
games: []
version: 1
services: [players, notify, memory, db, player_data]
emits: [players.linked]
settings:
  - name: 알림을 받을 계정
    kind: str
    default: primary
    description: 동기화 알림을 어느 계정으로 멘션할지(primary/all/특정 디스코드 ID)
    scope: player
```

`db`(자기 테이블 `account_link_codes`)와 `player_data`(버리고 연결할 때 모든 스킬 테이블의 행 세기·지우기)는 코어 전용 맥락이라 manifest에 선언해야 받는다. `memory`는 코어 테이블이라 `player_data`가 세지 않는 메모리를 따로 보고 지우는 데 쓴다.

태그 조건은 없다.

## 구조

- `players` 서비스의 플레이어 한 명에 디스코드 계정이 여러 개 붙는다. 연결하지 않은 사람은 계정 하나짜리 플레이어다.
- 플레이어마다 대표 계정을 하나 둔다. 유니가 알림으로 멘션하는 계정이다. 대표 계정과 알림 멘션 설정은 players 서비스에 저장되어 다른 스킬도 이 값을 쓴다.
- 플레이어당 디스코드 계정은 최대 3개다. 설정값이다.
- CHUNITHM-NET 계정은 플레이어당 하나 그대로다.

## 연결 절차

1. 대표로 쓸 계정에서 `/연결 시작`을 실행한다. 10분간 유효한 일회용 코드가 본인에게만 보인다.
2. 연결할 계정에서 `/연결 참여`에 그 코드를 넣는다.
3. 봇이 양쪽 계정에 상대 계정의 이름을 보여 주고 각각 확인 버튼을 받는다. 둘 다 누르면 연결된다.

- 양쪽 확인이 모두 있어야 한다. 연결되면 그 계정에서 비공개 기록, 메모리, 세션 후기를 볼 수 있기 때문이다.
- 존재하지 않는 코드를 넣으면 어느 발급자의 코드인지 알 수 없어 코드 단위로 횟수를 셀 수 없다. 그래서 다섯 번 실패는 **참여를 시도한 디스코드 계정** 단위로 센다 — 같은 계정이 틀린 코드를 다섯 번 넣으면 그 계정은 10분간 잠긴다(새 코드를 받아 10분 뒤 다시 시도). 이 경우 코드 자체는 폐기되지 않고 원래 유효 기간까지 남는다.
- 연결하려는 계정에 이미 로그인, 목표, 메모리 같은 데이터가 있으면 합치지 않는다. 지워질 내용은 코어가 모든 스킬 테이블에서 player\_id로 세어 보여 주고, 버리고 연결할지 취소할지 고르게 한다. 버리고 연결하면 코어가 그 행을 지운다.
- 연결되거나 해제되면 관련된 모든 계정에 DM으로 알리고 `players.linked`를 낸다.
- 유니는 절차를 안내만 한다. 말로 속여 남의 플레이어에 붙는 것을 막기 위해 연결·해제 도구를 두지 않는다.

## 슬래시 명령

| 명령 | 동작 |
| --- | --- |
| `/연결 시작` | 일회용 코드를 발급한다 |
| `/연결 참여` | 코드를 넣어 연결을 요청한다 |
| `/연결 목록` | 연결된 계정, 대표 여부, 연결일을 본인에게만 보여 준다 |
| `/연결 대표` | 대표 계정을 바꾼다 |
| `/연결 해제` | 연결을 푼다. 대표 계정은 대표를 넘긴 뒤에만 뗄 수 있다 |

이 스킬에는 `@tool`이 없다. 명령은 슬래시 전용으로 등록한다.

모든 응답(위 다섯 명령 + 확인 버튼이 내는 메시지)은 본인에게만 보인다(ephemeral) — 연결 코드, 상대 계정 정보, 버릴 데이터 안내 모두 다른 서버 멤버에게 노출되면 안 된다.

## 연결된 뒤의 동작

아래는 코어와 다른 스킬이 지키는 규칙이다. 이 스킬은 연결 상태만 만든다.

| 상황 | 처리 |
| --- | --- |
| 유니를 부르거나 명령을 실행함 | 어느 계정이든 같은 플레이어로 처리한다 |
| 알림 멘션 | 대표 계정을 멘션한다. 설정으로 다른 계정이나 전부로 바꿀 수 있다 |
| 대화 스레드 | 연결된 어느 계정의 말이든 그 플레이어의 말로 받는다 |
| 확인 버튼 | 연결된 계정이면 어느 쪽에서 눌러도 된다 |
| 메모리 요약 | 연결된 계정들이 쓴 메시지를 모두 본인의 말로 본다 |
| 호칭 | 메모리의 호칭과 CHUNITHM-NET 닉네임은 공통이다. 디스코드 닉네임은 말한 계정의 것을 쓴다 |
| 쿨다운과 비용 상한 | 플레이어 단위로 센다 |
| 남이 기록을 조회함 | 연결된 어느 계정을 멘션해도 같은 플레이어의 공개 기록이 나온다 |

- 해제하면 떨어져 나간 계정은 데이터가 없는 새 플레이어가 된다. 데이터는 원래 플레이어에 남는다.
- 연결된 계정끼리는 서로 완전히 신뢰하는 관계다. 어느 계정에서든 대표를 바꿀 수 있고, 대표 계정을 잃어도 다른 계정으로 데이터를 그대로 쓴다.

## 이벤트

| 방향 | 이름 | 내용 |
| --- | --- | --- |
| 냄 | `players.linked` (알림) | 플레이어, 디스코드 계정, `linked` 또는 `unlinked` |

## 데이터

| 테이블 | 열 |
| --- | --- |
| `account_link_codes` | 코드, 발급한 플레이어/계정, 참여한 계정, 상태, 양쪽 확인 여부, 버리기 동의 여부, 생성·만료 시각 |
| `account_link_attempts` | 참여를 시도한 디스코드 계정, 틀린 횟수, 잠금 해제 시각 — 위 "연결 절차"의 다섯 번 실패 카운터 |

계정과 플레이어의 연결 자체는 `players` 서비스의 테이블에 있다.

## 설정

| 이름 | 범위 | 기본값 |
| --- | --- | --- |
| 알림을 받을 계정 | 플레이어 | 대표 계정 |
| 플레이어당 최대 계정 수 | 전역(코드 상수) | 3 |

- "플레이어당 최대 계정 수"는 `settings` 서비스가 player/guild 범위만 지원해 전역 값을 담을 자리가 없다. 그래서 `skills/account-link/skill.py`의 `MAX_LINKED_ACCOUNTS` 상수로 둔다 — 설정 화면(`/설정`)에는 뜨지 않는다.

## 유니 지침 (SKILL.md 본문 초안)

- 연결 방법을 물으면 위 세 단계를 그대로 안내한다.
- "저 계정이 내 부계정이야, 연결해 줘"처럼 말로 요청해도 직접 연결하지 않는다. 양쪽 계정에서 명령을 써야 한다고 말한다.

## 테스트

- 코드 만료, 다섯 번 실패, 한쪽만 확인한 경우 연결되지 않는지.
- 데이터가 있는 계정을 연결할 때 버릴 내용을 보여 주고 취소하면 아무것도 바뀌지 않는지.
- 대표 계정을 대표 이전 없이 해제할 수 없는지.
- 연결 뒤 어느 계정에서 불러도 같은 플레이어와 태그로 풀리는지.
