# 유니 스킬: chunithm-session

Oct 9, 2026 · @astrove

동기화 리포트를 플레이 날짜별 세션으로 그대로 보관하고, 날짜나 오락실로 다시 불러오며, 세션이 끝난 뒤 후기 대화를 남기는 스킬이다. 불러올 때는 저장된 요약을 그대로 보여 주고 지금의 유니가 짧게 덧붙인다.

## 개요

```yaml
name: chunithm-session
description: 지난 플레이 세션을 날짜나 오락실로 찾아 불러오고, 세션 후기를 남기거나 본다.
examples:
  - 10월 세션 언제언제 했었지?
  - 가장 최근 겜플 세션 불러와 줘
  - 10월 5일 후기 남길게
category: 세션과 후기
game: chunithm
version: 1
services: [records, arcades, yuni, notify, players]
tags: [chunithm-synced]
listens: [chunithm.sync.reported]
emits: [chunithm.session.closed, chunithm.session.viewed]
```

## 세션

- **단위**: 플레이어의 플레이 날짜 하루가 세션 하나다. 세션 id와 날짜 배정은 `records` 서비스가 만든다. 자정을 넘긴 플레이는 날짜 경계(기본 새벽 4시) 전까지 전날 세션에 붙고, 이력에 없는 갱신은 그 동기화의 마지막 날짜에 넣으며 추정임을 표시한다.
- **보관**: `chunithm.sync.reported`를 받으면 그 리포트의 표시물과 조각별 `data`, 유니의 한마디를 세션별로 고정해 저장한다. 나중에 상수가 바뀌거나 기록이 갱신돼도 저장된 요약은 변하지 않는다. 새 플레이가 없는 동기화는 보관하지 않는다.
- **오락실**: 세션에 붙은 오락실 방문은 `arcades` 서비스에 있다. 하루에 두 곳 이상을 갔으면 세션 하나에 오락실이 여러 개 붙는다. 동기화 때 오락실을 건너뛴 세션은 나중에 "10월 N일은 겜플이었어"처럼 말해 채울 수 있다.
- **보존**: 지우지 않는다. 플레이어는 자기 세션을 지울 수 있다.
- **공개 범위**: 기록 공개 설정을 따른다. 본인만 보기 설정인 플레이어의 세션은 리포트와 같은 방식(숨김 메시지나 DM)으로 보여 준다.

## 찾기

| 요청 | 동작 |
| --- | --- |
| "10월 세션 언제 했지?" | 그 달의 세션 날짜를 나열한다. 날짜마다 오락실과 레이팅 변화를 한 줄로 붙인다 |
| "가장 최근 세션 어땠어?" | 마지막 세션의 저장된 요약을 보여 준다 |
| "10월 N일 세션 불러와 줘" | 그 날짜의 저장된 요약을 보여 준다 |
| 그 날짜에 세션이 없음 | 없다고 알리고 가장 가까운 앞뒤 세션 날짜를 제안한다 |
| 기간만 말함 ("지난달") | 목록을 먼저 보여 주고 고르게 한다 |
| "가장 최근 게임플라자 세션" | `ArcadeRef`로 오락실을 풀고, 그곳에서의 마지막 세션을 보여 준다 |
| "겜플에서 언제 쳤지?" | 그 오락실에서의 세션 날짜를 나열한다 |
| "10월에 겜플 간 날" | 기간과 오락실을 함께 걸러 나열한다 |
| 그 오락실에서의 세션이 없음 | 없다고 알리고, 방문 기록이 있는 오락실 목록을 보여 준다 |

- 날짜 해석("지난달", "어제")은 모델이 날짜 인자로 바꿔 넘기고, 세션을 찾는 것은 코드가 한다.
- 목록에는 오락실별 세션 횟수와 마지막 방문일도 낼 수 있다.

## 불러온 세션의 모양

1. **저장된 요약**: 당시 리포트 그대로. 저장된 기록임과 날짜를 위에 표시한다. 당시 유니의 한마디도 여기 있다.
2. **그날의 오락실과 설정**: `arcades` 서비스의 방문 기록과, `chunithm-arcade`가 저장한 그날 게임 설정(있으면).
3. **그 뒤의 변화**: 그날 갱신한 채보와 전체 레이팅의 현재값을 코드가 계산해 나란히 보여 준다. 예: 그날 SS+였던 곡이 지금은 SSS.
4. **후기**: 있으면 붙인다. 길면 앞부분만 보여 주고 전체 보기 버튼을 둔다.
5. **유니의 덧붙임**: 멘션으로 불렀을 때만. 지금의 메모리와 위 내용을 보고 한두 문장으로 말한다. 슬래시로 부르면 빠진다.

오락실 설정을 보여 주는 부분은 `chunithm-arcade` 테이블을 직접 읽지 않는다. 세션을 불러올 때 모으기 이벤트 `chunithm.session.viewed`를 내고, 오락실 스킬이 그날 설정 조각을 돌려준다.

## 세션 후기

**시작**

- 새 플레이가 있는 리포트를 보관한 뒤, 유니가 묻는다. 예: "○○상, 이번에 어땠어?"
- 코어의 대화 스레드를 DM에서 연다(2026-10-19 결정: 공개 리포트도 DM에서 한다. 리포트 메시지 아래 비공개 스레드는 동기화가 보낸 메시지 id를 스킬까지 넘기는 길이 없어 뒤로 미룸). 후기는 본인만 보는 글이라 DM이 성격에도 맞다. 연결된 계정 중 대표 계정으로 연다.
- 스레드 안에서는 그 플레이어(연결된 어느 계정이든)의 메시지에 멘션 없이 답한다.
- 플레이어가 지금은 넘기겠다고 하면 후기 없이 닫는다. 나중에 "10월 N일 후기 남길게"라고 하면 그 세션의 후기를 연다.
- 한 동기화에 세션이 여러 날이면 가장 최근 세션에 대해서만 묻는다.

**대화의 흐름**

| 유니가 하는 것 | 유니가 하지 않는 것 |
| --- | --- |
| 플레이어의 말에 짧게 반응하고 답한다 | 분석이나 조언을 먼저 길게 늘어놓지 않는다 |
| 가끔 간단한 질문을 하나 던진다 | 질문을 연달아 하거나 캐묻지 않는다 |
| 리포트에 있는 숫자를 인용한다 | 리포트에 없는 숫자를 지어내지 않는다 |
| 물어보면 도구를 써서 답한 뒤 후기로 돌아온다 | 화제를 자기 쪽으로 끌고 가지 않는다 |

- 유니의 말은 한두 문장으로 제한한다. 질문은 서너 번 주고받을 때 한 번 정도, 한 번에 하나만.
- 후기용 지침을 따로 두어 평소의 멘션 응답보다 말을 줄인다. 이 지침은 스레드 안에서만 프롬프트에 들어간다.

**끝내기** (코어의 대화 스레드가 처리)

| 상황 | 처리 |
| --- | --- |
| 플레이어가 끝났다고 말함 | 유니가 짧게 마무리하고 종결한다. 애매하면 끝낼지 되묻는다 |
| 끝내기 버튼을 누름 | 판단 없이 바로 종결한다 |
| 5분 넘게 말이 없음 | 유니가 끝났는지 묻는다 |
| 물은 뒤 다시 5분 넘게 말이 없음 | 종결한다 |
| 물었을 때 아직이라고 답함 | 대화를 이어 가고 시간을 다시 잰다 |
| 대화 중에 봇이 꺼짐 | 그때까지의 전문을 저장하고 중단으로 표시한다. 켜진 뒤 이어서 남길 수 있다 |

두 번의 5분은 설정값이다.

**저장**

- 종결하면 코어가 넘겨주는 대화 전문을 그대로 저장한다. 요약하거나 다듬지 않는다.
- 같은 세션에 후기를 더 남기면 기존 후기 뒤에 이어 붙인다.
- 후기는 본인만 볼 수 있다. 기록 공개 설정으로 세션이 남에게 보이는 경우에도 후기는 따로 공개해야 보인다.
- 저장한 뒤 `chunithm.session.closed`를 낸다. 코어는 평소처럼 메모리 요약을 돌린다. 후기 대화 중에 나온 다음 약속은 유니가 그 자리에서 `yuni-bond`의 `promise_set`으로 저장한다.

## 도구

| 함수 | 하는 일 | 인자 | 슬래시 | display | confirm |
| --- | --- | --- | --- | --- | --- |
| `list` | 세션 목록 (표 반환) | 날짜 또는 기간, `arcade: ArcadeRef`(선택), `player: PlayerRef` | `/세션 목록` | 표 | never |
| `get` | 세션 하나 불러오기(후기 포함) | 날짜, `arcade: ArcadeRef`(선택), `latest: bool`, `player: PlayerRef` | `/세션 보기` | required | never |
| `review_open` | 후기 스레드 열기 | 날짜(기본 최근) | `/후기` | optional | never |
| `delete` | 내 세션 지우기 | 날짜 또는 기간 | `/세션 삭제` | optional | always |

후기의 종결은 코어의 대화 스레드가 처리하므로 닫는 도구는 두지 않는다. 후기를 공개로 바꾸는 것은 `get`의 버튼으로 한다.

## 유니 지침 (SKILL.md 본문 초안)

- 날짜 표현은 현재 날짜 기준으로 실제 날짜나 기간으로 바꿔 넘긴다.
- 불러온 세션에 덧붙일 때는 한두 문장만. 당시와 지금의 차이 중 눈에 띄는 것 하나를 짚는다. 숫자는 도구 `data`의 값만 쓴다.
- 후기 스레드 안에서는 위 "대화의 흐름" 표를 따른다.

## 테스트

- 새 플레이 없는 동기화는 보관하지 않는지.
- 저장된 요약이 이후 상수 변경에 바뀌지 않는지.
- 날짜·기간·오락실 조합 검색과 없을 때의 제안.
- 후기 종결 시 전문이 그대로 저장되고, 이어 남기기가 뒤에 붙는지.
- 후기가 세션 공개와 별개로 비공개인지.

## 구현 결정 (2026-10-17, 7단계 계획서에서 옮김 — 구현 전)

- 7단계에서는 보관과 조회(`list`/`get`/`delete`)만 만들었고, 후기는 12단계 Part 3(2026-10-19)에서 더했다(아래 "구현 결정 (2026-10-19, 12단계 Part 3)").
- 그때까지는 `chunithm.sync.reported`를 받아도 대화 스레드를 열지 않고 보관만 했다.
- 조회 도구는 본인을 조회할 때 공개 설정을 보지 않고, 남을 조회할 때만 그 사람의 공개 설정을 확인한다.

## 구현 결정 (2026-10-18, Part 3 구현 중)

- (2026-10-18 Part 3 당시) `chunithm-sync`의 `run()`이 `chunithm.sync.reported` payload에 실어 보내는 `arcade_id`를 저장하는 코드가 없어, 이 스킬의 `on_sync_reported`가 `arcades.record_visit()`을 직접 불러 임시로 받았다. **8단계(`chunithm-arcade`)가 생기면서 이 호출은 그쪽으로 옮겼다** — `chunithm-arcade`가 방문 기록과 그날 설정 읽기를 한 이벤트 핸들러에서 같이 하는 게 맞고, 두 스킬이 같은 `arcade_id`를 보고 각자 `record_visit()`을 부르면 방문이 중복 기록된다. 이 스킬은 `session_reports` 저장만 한다.
- 같은 세션(날짜)에 다시 동기화하면 `session_reports`는 세션당 한 행이라 최신 리포트로 바뀐다. 다만 그 리포트가 **그날 하루치**다(2026-10-21 결정, 이전엔 마지막 동기화 것만 남아 앞선 갱신이 사라졌다): `records` 서비스가 세션마다 누적 비교 데이터(`records_session_state`: 세션 시작 시점의 레이팅·평균, 채보별 갱신, 미갱신 플레이, 프레임 이탈)를 보관하고, 같은 날 다음 동기화가 그 위에 더해 `SyncDiff`를 만든다. 같은 채보가 또 갱신되면 이전 값은 하루 시작 때 것, 새 값은 마지막 것이다. 갱신된 채보는 미갱신에서 빠지고, 미갱신 플레이는 횟수가 합쳐진다. 그래서 동기화 응답도 하루치로 나온다.
- `get_session`은 설계서의 `latest: bool` 인자를 받지 않는다 — `date`를 안 주면 항상 최근(또는 arcade로 좁힌 범위의 최근)이라 의미가 같은 플래그를 따로 두지 않았다.
- 오락실 "설정"(그날 게임 설정)은 설계서대로 `chunithm.session.viewed`로 모으기만 하고, "방문"(어느 오락실)은 공통 `arcades` 서비스를 직접 읽는다 — 방문은 `arcades` 서비스 자체로 이미 존재하는 정보라 모으기를 거칠 필요가 없다. `record_visit`은 visited_at을 "지금"(동기화 시각, UTC)으로 남겨 플레이 날짜(새벽 4시 경계, 로컬)와 어긋날 수 있다는 근사값 한계는 그대로 남아 있다.

## 구현 결정 (2026-10-19, 12단계 Part 3)

- **DM에서만 연다.** 리포트 아래 비공개 스레드는 만들지 않았다. 동기화 도구가 보낸 메시지의 채널·메시지 id를 스킬이 모르고(`sent_location.channel_id`가 비어 있다), 스레드를 만들고 계정을 초대하는 코드도 없다. 후기는 본인만 보는 글이라 DM이 성격에도 맞다. 스레드로 바꾸려면 코어가 보낸 메시지 id를 도구 결과에 실어 주는 길부터 만든다. `NotifyService.open_dm_thread`가 DM 채널을 열고(`DiscordGateway.open_dm_channel`) 첫 말에 끝내기 버튼을 붙여 대화를 연다.
- **언제 묻나.** `chunithm.sync.reported`를 받아 보관한 뒤, 새 플레이가 있고 "후기 물어보기"(플레이어 설정, 기본 꺼짐 — 2026-10-21 사용자 결정: 후기는 사용자가 쓰자고 할 때만 연다)가 켜져 있고 이 플레이어의 후기 대화가 열려 있지 않을 때 가장 최근 세션 하나에 대해서만 묻는다. 그 세션에 후기가 이미 있으면(완료·넘김) 다시 묻지 않고, 봇이 꺼져 중단된 후기는 다음 동기화에서 다시 묻는다. 공개 리포트보다 질문이 먼저 가지 않도록 4초 기다렸다 보낸다(`_ASK_DELAY_SECONDS`). 첫 마디는 `yuni.line`이 만들고(단계 없는 한마디, 숫자 없는 힌트) 실패하면 "이번엔 어땠어?"를 쓴다.
- **`/후기`(`review_open`)** 는 "후기 물어보기" 설정과 상관없이 연다. 날짜를 안 주면 가장 최근 세션이고, 이미 열린 후기가 있거나 DM을 열 수 없으면 오류를 돌려준다.
- **무응답 시간**은 설계서의 한 줄 설정을 둘로 나눴다: "후기 무응답 확인 시간"·"후기 종결 시간"(서버 범위, 분, 기본 5). DM에서는 서버가 없어 기본값을 쓴다.
- **끝내기.** 말로 끝내기는 스레드 안에서만 모델에게 보이는 코어 도구 `end_conversation`이 맡는다(마무리 말을 보낸 뒤 코어가 닫는다. 애매하면 도구 설명대로 되묻는다). 버튼은 판단 없이 바로 닫는다(`core/thread_view.py`, 대화의 플레이어 본인만 누를 수 있다).
- **후기용 지침**은 `ThreadSession.guidance`로 스킬이 정하고, 코어가 그 대화의 프롬프트 "맥락"에만 넣는다. 안에 그 세션의 저장된 리포트 앞 1500자가 들어 있다(숫자 인용용).
- **저장.** `session_reviews`(`migrations/002_reviews.sql`)에 전문(유니와 플레이어의 말, 시각)을 JSON으로 그대로 저장한다. 상태는 플레이어가 한마디라도 했으면 완료(봇이 꺼져 닫혔으면 중단), 아니면 넘김. 같은 세션에 다시 남기면 메시지를 뒤에 잇고(넘김은 기존 후기를 건드리지 않는다), 세션을 지우면 후기도 지운다(외래키가 꺼져 있어 코드가 지운다). 저장 뒤 `chunithm.session.closed`(플레이어, 세션 id, 저장 여부, 상태, 닫힌 이유, 전문 글)를 낸다.
- **보기.** `get_session`이 본인에게만 후기를 붙인다(길면 앞 600자). 공개로 바꾸는 버튼과 "전체 보기" 버튼은 아직 없다(후기는 항상 비공개).
- 전문의 유니 발언은 코어 `ThreadMessage.is_yuni`로 구분하며, 메모리 요약 대기 목록에는 플레이어 글만 들어간다.

## 표로 바꾼 읽기 도구 (16단계 Part 4-3, 2026-10-20)

`list`(코드 이름 `list_sessions`)는 표를 돌려준다(표 모양·서식은 `docs/plan/2026-10-20_수정.md` §16 Part 4의 4-1·4-2). 가리키는 것 `chunithm-session.session` = 세션 id. 칸 날짜·추정(글자 출력에서 숨김)·오락실·갱신 채보 수. 추정 세션은 날짜 칸의 보일 글자에 " (추정)"이 붙는다. 오락실을 모르는 세션은 두 번째 서식으로 오락실 없이 그려진다. 과정(steps)에 기간·오락실 조건이 붙는다. 세션이 없으면 표 없이 문장만 낸다. `data`의 `sessions`는 그대로 둔다.
