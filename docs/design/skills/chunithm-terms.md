# 유니 스킬: chunithm-terms

Oct 9, 2026 · @astrove

츄니즘 용어와 은어의 뜻을 설명하는 스킬이다. 용어 데이터는 `terms` 서비스에 있고, 랭크·난이도·램프·점수처럼 값이 되는 용어는 이 스킬이 아니라 코어의 표준 인자 타입이 해석한다. 그래서 이 스킬을 꺼도 다른 스킬은 "트플플"을 그대로 알아듣는다.

## 개요

```yaml
name: chunithm-terms
description: 츄니즘 용어와 은어(트플플, 이론치, 오버파워, 비비기 등)의 뜻을 설명하고, 서버에서 쓰는 은어를 등록한다.
examples:
  - 오버파워가 뭐야?
  - 트플플이 몇 점부터야?
  - 비비기가 뭐야?
category: 질문 답변
game: chunithm
version: 1
services: [terms, players, notify]
```

태그 조건은 없다. 서버 은어 승인 도구만 `admin`이 필요하다.

## 용어의 두 종류

| 종류 | 예 | 해석하는 곳 | 추가 방법 |
| --- | --- | --- | --- |
| 값 용어 | 랭크, 난이도, 램프, 점수 표현 | 코어의 `RankRef`, `DifficultyRef`, `LampRef`, `ScoreRef` | `terms.yaml` 수정으로만. 잘못 들어가면 계산이 틀어지기 때문이다 |
| 개념 용어 | 오버파워, 상수, 저스티스 크리티컬, 비비기(안미츠), 판정 A·B, 베스트 프레임 | 이 스킬 | `terms.yaml`, 또는 서버에서 제안하고 `admin`이 승인 |

**값 용어의 해석 (코어 표준 타입)**

- 모델은 "트플플", "마스", "이론치", "1007.5k"처럼 들은 말을 그대로 넘기고, 코어가 `terms` 서비스로 정식 값(SSS+ → 1,009,000 등)으로 바꿔 함수에 넘긴다.
- 모르는 말이면 함수는 불리지 않고 "후보: SSS+, SSS" 같은 오류가 모델에 돌아간다. 모델이 점수 기준을 기억으로 판단하지 않는다.
- 점수 표현은 "1007.5k", "100만 7천5백", "1,007,500"을 모두 같은 값으로 읽는다.

## 용어 항목의 형식

| 칸 | 내용 |
| --- | --- |
| 정식 표기 | 예: SSS+ |
| 분류 | 랭크, 난이도, 램프, 점수, 판정, 개념, 기술 |
| 별칭 | 한국어, 일본어, 영어 별칭 목록 |
| 값 | 값 용어만. 예: 1,009,000 |
| 뜻 | 한두 문장 |
| 출처 | 확인한 링크. 없으면 "서버 사용"으로 표시 |
| 범위 | 전역(`terms.yaml`) 또는 서버 |

**항목 예시** (형식을 보여 주기 위한 것이다. 실제 목록은 플레이어들이 쓰는 말을 모아 확인한 뒤 넣는다)

```yaml
- canonical: SSS+
  category: rank
  aliases: [트플플]
  value: 1009000
  meaning: 1,009,000점 이상. 최고 랭크.
- canonical: SSS
  category: rank
  aliases: [트리플]
  value: 1007500
- canonical: AJC
  category: lamp
  aliases: [이론치]
  value: 1010000
  meaning: 모든 노트를 저스티스 크리티컬로 친 만점.
- canonical: 안미츠
  category: technique
  aliases: [비비기]
  meaning: 타이밍이 조금 다른 두 노트를 동시에 쳐서 저스티스 크리티컬 판정 안에 넣는 기술.
```

## 서버 은어

- 플레이어는 `/용어 제안`이나 유니에게 말로 개념 용어를 제안할 수 있다. 제안은 바로 반영되지 않고, `admin` 태그를 가진 플레이어가 승인해야 반영된다.
- 값 용어의 별칭은 서버에서 추가할 수 없다. 제안이 들어오면 관리자에게 `terms.yaml`에 넣을 후보로 알린다.
- 서버 은어는 그 서버에서만 쓴다. 전역 용어와 충돌하면 전역 용어가 이긴다.

## 다른 스킬과의 관계

- **web-qa**: 용어 사전에 있는 말은 웹 검색 없이 이 스킬로 답한다. 없는 말만 `web-qa`로 넘어간다. 검색으로 찾은 뜻은 서버 용어 제안으로 남길 수 있다.
- **표기**: 표시물(임베드·표)은 항상 정식 표기를 쓴다. 유니의 말은 플레이어가 쓴 표현을 따라갈 수 있다. 예: "트플플까지 3.20어택이에요."

## 도구

| 함수 | 하는 일 | 인자 | 슬래시 | 태그 | display | confirm |
| --- | --- | --- | --- | --- | --- | --- |
| `explain` | 용어의 뜻, 별칭, 값, 출처 | `term` | `/용어 뜻` | 없음 | optional | never |
| `list` | 분류별 용어 목록 | `category`(선택) | `/용어 목록` | 없음 | required | never |
| `suggest` | 서버 은어 제안 | `term`, `meaning`, `aliases` | `/용어 제안` | 없음 | optional | never |
| `review` | 제안 승인·거절 | 제안 id, 결정 | `/용어 승인` | `admin` | optional | always |

## 이벤트

내거나 받는 이벤트는 없다.

## 데이터

| 위치 | 내용 |
| --- | --- |
| `services/chunithm/data/terms.yaml` | 전역 용어(값 용어와 개념 용어). 저장소에서 검토해 고친다 |
| `terms_server` 테이블 (`terms` 서비스 소유, `migrations/core/`에서 만든다) | 서버, 용어, 뜻, 별칭, 제안한 플레이어, 상태(제안·승인·거절), 승인한 플레이어 |

## 유니 지침 (SKILL.md 본문 초안)

- 용어 뜻은 사전에 있는 내용만 말한다. 사전에 없으면 `web-qa`를 펼친다.
- 랭크·램프의 점수 기준은 도구 결과의 값만 쓴다.
- 서버 은어를 설명할 때는 이 서버에서 쓰는 말이라고 밝힌다.
- 플레이어가 모르는 은어를 써서 해석에 실패하면, 뜻을 물어보고 용어 제안을 권할 수 있다.

## 테스트

- 별칭이 같은 정식 값으로 풀리는지(`RankRef`, `LampRef` 등).
- 점수 표현 여러 형식의 해석.
- 값 용어의 별칭을 서버에서 추가할 수 없는지.
- 승인 전 제안이 해석과 설명에 쓰이지 않는지.
- 서버 용어가 다른 서버에서 보이지 않는지.

## 미확인 사항

- 초기 용어 목록. 한국 커뮤니티 용어를 정리한 출처를 검색으로 찾지 못했다. 플레이어들이 실제로 쓰는 말을 먼저 모으고, 확인한 것만 넣는다.
