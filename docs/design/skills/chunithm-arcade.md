# 유니 스킬: chunithm-arcade

Oct 9, 2026 · @astrove

동기화할 때 어느 오락실에서 쳤는지 묻고, 그 시점의 게임 설정을 CHUNITHM-NET에서 읽어 그 오락실 이름 아래에 저장하는 스킬이다. 나중에 이름이나 줄임말로 물으면 마지막 플레이 날짜와 함께 꺼내 준다. 오락실 목록, 별칭, 방문 기록은 게임과 무관하므로 `arcades` 공통 서비스에 있고, 이 스킬은 츄니즘 게임 설정만 갖는다.

## 개요

```yaml
name: chunithm-arcade
description: 오락실별로 츄니즘 게임 설정(스피드, 필드 월, 판정 A·B, 가이드음)을 저장하고 꺼내 보여 준다.
examples:
  - 겜플 세팅 알려 줘
  - 게임플라자 설정 바뀐 거 보여 줘
category: 오락실
game: chunithm
version: 1
services: [chunithm_net, arcades, records]
listens: [chunithm.sync.completed, chunithm.session.viewed]
```

## 저장하는 설정

| 항목 | 비고 |
| --- | --- |
| 스피드 |  |
| 필드 월 |  |
| 판정 타이밍 A | −2.0부터 +2.0. 곡에 대한 채보 위치 조정 |
| 판정 타이밍 B | −2.0부터 +2.0. 노트 판정 시점 조정 |
| 가이드음 볼륨 | 0부터 10 |

- 기체 종류는 구분하지 않는다. 국내에는 구기체만 있으므로 오락실마다 기체를 묻거나 기록하지 않는다.
- 설정 페이지에 기체별 값이 두 벌로 보이면 국내 기체에 해당하는 쪽을 읽는다. 일본판은 별도 서버라 동기화 대상이 아니다.
- 페이지에 보이는 나머지 설정도 통째로 함께 저장해 둔다. 나중에 보여 줄 항목을 늘릴 수 있다.
- chuni-penguin 어댑터에는 게임 설정 페이지를 읽는 코드가 없다. 파서를 새로 만들어 `chunithm_net` 서비스에 더한다.

## 동기화 때의 흐름

1. 동기화 리포트에 새 플레이가 있으면, 이 스킬의 조각(order 50)이 어디서 쳤는지 묻는다. 최근에 간 오락실 세 곳, 다른 곳, 건너뛰기를 버튼으로 낸다.
2. 다른 곳을 고르면 이름을 입력받아 아래의 이름 확인을 거친다.
3. 오락실이 정해지면 `arcades` 서비스에 방문(세션 id, 마지막 플레이 날짜)을 남기고, CHUNITHM-NET의 현재 설정을 읽어 그 방문에 저장한다.
4. 직전에 저장된 값과 달라진 항목이 있으면 버튼 응답에 한 줄로 짚는다.

- 새 플레이가 없으면 묻지 않는다.
- 두 곳 이상에서 쳤다면 여러 곳을 고를 수 있다. 설정은 계정에 하나뿐이므로 마지막으로 친 곳에만 저장하고, 나머지는 방문만 남긴다.
- 멘션에 오락실 이름이 이미 들어 있으면("겜플에서 친 거 동기화해 줘") 버튼 대신 이름 확인으로 바로 넘어간다.
- 플레이 이력에 점포 이름이 표시된다면 묻는 대신 그 이름을 후보로 제안한다(표시 여부 미확인).

## 이름 확인 (`arcades` 서비스와 `ArcadeRef`가 하는 일)

| 입력 | 처리 |
| --- | --- |
| 등록된 이름이나 별칭과 정확히 같음 | 묻지 않고 그 오락실로 처리 |
| 비슷한 후보가 하나 있음 | 그 오락실이 맞는지, 새 오락실인지 버튼으로 묻는다. 맞다고 하면 입력한 말을 별칭으로 저장 |
| 비슷한 후보가 여럿 있음 | 후보 목록과 새 오락실을 함께 보여 주고 고르게 한다 |
| 후보가 없음 | 새 오락실로 등록할지 묻는다 |

- 예: "광주 게임플라자"가 등록된 상태에서 "겜플"이 들어오면, 광주 게임플라자가 맞는지 새 오락실인지 묻는다. 맞다고 하면 "겜플"이 별칭으로 저장되어 다음부터는 묻지 않는다.
- 후보는 코드가 찾는다. 공백과 대소문자를 뺀 부분 일치, 어절 앞글자 조합, 자모 단위의 유사도를 쓴다. 멘션 경로에서는 모델이 줄임말을 풀어 후보를 더할 수 있다.
- 어느 경우든 저장 전에 플레이어가 버튼으로 확정한다. 모델의 추측만으로 별칭을 저장하지 않는다.
- 같은 별칭이 플레이어마다 다른 곳을 가리킬 수 있다. 별칭은 플레이어별로 저장하고, 오락실 목록은 서버가 함께 쓴다.

## 꺼내 보기

- "겜플 세팅 알려 줘"라고 하면 그 오락실에서 마지막으로 저장한 설정과 마지막 플레이 날짜를 보여 준다.
- 지금 계정의 설정(마지막으로 읽은 값)과 다른 항목이 있으면 함께 표시한다. 오락실에 도착해서 무엇을 바꿔야 하는지 바로 알 수 있다.
- 같은 오락실의 지난 설정 변화도 날짜순으로 볼 수 있다.
- 방문 기록과 설정은 기본 비공개다. 기록 공개 설정과 별도로 켠다.
- 세션을 불러올 때(`chunithm.session.viewed`) 그날 저장한 설정을 조각으로 돌려준다.

## 도구

| 함수 | 하는 일 | 인자 | 슬래시 | display | confirm |
| --- | --- | --- | --- | --- | --- |
| `get_settings` | 그 오락실의 마지막 설정과 지금 계정 설정의 차이 | `arcade: ArcadeRef` | `/오락실 설정` | optional | never |
| `history` | 그 오락실의 설정 변화 | `arcade: ArcadeRef` | `/오락실 기록` | required | never |
| `record_visit` | 세션에 오락실 방문을 남기고 지금 설정을 저장. 도구 태그 chunithm-linked, cost network | `arcade: ArcadeRef`, 날짜(기본 최근 세션) | `/오락실 방문` | optional | never |
| `set_privacy` | 방문 기록과 설정 공개 여부 | `public: bool` | 없음 | optional | never |

`record_visit`는 동기화의 버튼 흐름과 같은 함수다. 설정 읽기는 가장 최근 세션에만 한다. 지난 날짜에 오락실을 채우는 경우는 그날 설정을 알 수 없으므로 방문만 남긴다.

## 이벤트

| 방향 | 이름 | 돌려주는 것 |
| --- | --- | --- |
| 받음 | `chunithm.sync.completed` (모으기) | 오락실 선택 버튼 조각. 새 플레이가 없으면 없음 |
| 받음 | `chunithm.session.viewed` (모으기) | 그날 저장한 설정 조각 |

## 데이터

| 테이블 | 열 |
| --- | --- |
| `arcade_settings` | 방문 id(`arcades` 서비스), 스피드, 필드 월, 판정 A, 판정 B, 가이드음 볼륨, 나머지 설정 전체, 읽은 시각 |
| `arcade_privacy` | 플레이어, 공개 여부 |

`arcades` 서비스에는 오락실(이름, 지역, 등록한 플레이어), 별칭(플레이어, 별칭, 오락실), 방문(플레이어, game, 오락실, 세션 id, 마지막 플레이 날짜)이 있다.

## 유니 지침 (SKILL.md 본문 초안)

- 오락실 이름이 확실하지 않으면 추측해서 저장하지 않는다. `ArcadeRef`가 돌려주는 후보 버튼으로 확정받는다.
- 설정을 물으면 지금 계정 설정과 다른 항목부터 말한다. 다른 항목이 없으면 그대로 쓰면 된다고 말한다.
- 마지막 플레이 날짜를 함께 말한다.

## 테스트

- 저장본 설정 페이지로 파서 테스트.
- 이름 확인의 네 가지 경우와 별칭 저장.
- 여러 곳을 고른 경우 설정이 마지막 곳에만 저장되는지.
- 차이 표시가 바뀐 항목만 나오는지.

## 미확인 사항

- 국제판 CHUNITHM-NET의 게임 설정 페이지 경로와 표시 항목. 로그인이 필요해 확인하지 못했다. 저장본을 받은 뒤 이 스킬을 시작한다.
- 플레이 이력 상세 페이지에 점포 이름이 표시되는지.
