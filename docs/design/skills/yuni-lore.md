# 유니 스킬: yuni-lore

2026-10-20 사용자 요청으로 추가한 스킬(계획에 없던 추가, 15단계). 유니와 나비, Linked VERSE 이야기를 플레이어가 물었을 때만 설정집을 읽어 답하게 한다.

## 개요

```yaml
name: yuni-lore
description: 유니와 나비가 누구인지, Linked VERSE 이야기가 어땠는지 설정집을 읽어 답한다. 유니 자신이나 이야기를 물을 때 쓴다.
examples:
  - 유니는 어디서 왔어?
  - 나비는 누구야?
  - Linked VERSE 스토리 알려줘
category: 유니 설정
games: []
version: 1
services: []
```

스킬 자체의 태그 조건은 없다. DB, 슬래시 명령, 이벤트, 설정은 없다. 대화로만 쓴다.

## 왜 스킬인가

`persona.md`는 매 요청마다 들어간다. 설정 전체를 넣으면 토큰이 늘고, 모델이 묻지 않은 스토리를 꺼낼 위험이 커진다(`rules`·`persona`의 "묻기 전에는 꺼내지 않는다"). 그래서 `persona.md`에는 유니·나비 소개 몇 줄만 두고, 자세한 설정은 플레이어가 물을 때만 이 스킬로 읽는다.

## 설정집

`skills/yuni-lore/lore.md` 한 곳에만 둔다(복사 금지). `## [id] 제목` 단위로 구간이 나뉘고, 제목 끝이 `(스포일러)`면 스포일러 구간이다.

| 묶음 | 구간 id |
| --- | --- |
| 기본 | `premise`, `characters`, `terms`, `favorite_game` |
| 이야기(게이트 순서) | `origin`, `air`, `star`, `amazon`, `crystal`, `paradise`, `after_patch` |
| 스포일러 | `gate9`, `gate10`, `x_verse`, `ending`, `hidden_message` |

원문은 `docs/persona/yuni-lines/`에 있고, 설정집에는 거기서 확인된 사실만 우리말로 적는다. 10년 뒤의 유니 이야기는 다루지 않는다(2026-10-20 사용자 지시).

## 도구

| 도구 | 하는 일 | 인자 | 슬래시 |
| --- | --- | --- | --- |
| `read_lore` | 구간 하나를 읽는다. 구간을 안 주면 목록(id, 제목, 스포일러 여부)만 돌려준다 | `section`(선택), `spoiler_ok`(선택) | 없음 |

- 스포일러 구간은 `spoiler_ok`가 꺼져 있으면 본문 없이 오류를 돌려준다. 플레이어에게 먼저 물어보라는 안내가 담긴다. 모델이 묻지 않고 켤 수는 있어서 지침으로도 묻게 한다.
- 모르는 구간 id에는 가능한 id 목록을 오류에 담는다. 설정집 파일이 없으면 오류.
- 게이트별로 나눈 것은 사용자 결정(2026-10-20)이다. 한 번에 다 주지 않아 토큰이 덜 들고 스포일러 경계가 분명해진다.

## 유니 지침 (SKILL.md 본문)

- 묻지 않은 설정을 먼저 꺼내지 않는다. 목록을 보고 물은 내용의 구간만 읽는다.
- 읽은 구간에 있는 내용만 말하고, 일본어 원문을 인용하지 않는다. 없으면 모른다고 한다.
- 스포일러 구간은 읽기 전에 괜찮은지 먼저 묻고, 괜찮다고 한 뒤에만 `spoiler_ok`를 켠다.
- 10년 뒤 이야기는 설정집에 없으니 말해 줄 수 없다고 넘긴다.

## 테스트

- manifest가 맞는지(이름, 분류), 목록에 스포일러 표시가 나오는지.
- 스포일러 구간 전부가 `spoiler_ok` 없이 막히고, 켜면 읽히는지.
- 요청한 구간만 돌려주는지, 모르는 id·파일 없음이 오류인지.
- 설정집에 10년 뒤 유니 표기(`イクシア`, `RE:VERSE`, `UNIVERSE` 등)가 들어가지 않았는지.

## 미확인 사항

- 실기: "유니는 어디서 왔어?"에 `read_lore`를 부르고 짧게 답하는지, "스토리 알려줘"가 `premise`나 `origin`부터 읽는지, 결말을 물으면 스포일러 확인을 먼저 하는지, 설정을 묻지 않은 대화에서 이 스킬을 안 펼치는지.
