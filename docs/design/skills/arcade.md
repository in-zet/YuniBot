# 유니 스킬: arcade

Oct 9, 2026 · @astrove

동기화할 때 어느 오락실에서 쳤는지 묻고, 그 시점의 게임 설정을 CHUNITHM-NET에서 읽어 그 오락실 이름 아래에 저장하는 스킬이다. 나중에 이름이나 줄임말로 물으면 마지막 플레이 날짜와 함께 꺼내 준다. 오락실 목록, 별칭, 방문 기록은 게임과 무관하므로 `arcades` 공통 서비스에 있고, 이 스킬은 츄니즘 게임 설정만 갖는다.

## 개요

```yaml
name: arcade
description: 오락실별로 츄니즘 게임 설정(스피드, 필드 월, 판정 A·B, 가이드음)을 저장하고 꺼내 보여 준다.
examples:
  - 겜플 세팅 알려 줘
  - 게임플라자 설정 바뀐 거 보여 줘
category: 오락실
game: chunithm
version: 1
services: [chunithm_net, arcades, records, db]
listens: [chunithm.sync.completed, chunithm.sync.reported, chunithm.session.viewed]
```

## 저장하는 설정

설정 페이지는 `/mobile/home/userOption/updateUserOption`, `<select>` 태그 값으로 저장돼 있다.

| 항목 | `<select name>` | 비고 |
| --- | --- | --- |
| 스피드 | `speed` |  |
| 필드 월 | `fieldWallPosition` |  |
| 판정 타이밍 A | `playTimingOffset` | −2.0부터 +2.0. 곡에 대한 채보 위치 조정 |
| 판정 타이밍 B | `judgeTimingOffset` | −2.0부터 +2.0. 노트 판정 시점 조정 |
| 가이드음 볼륨 | `guideSound` | 0부터 10 |

- 기체 종류는 구분하지 않는다. 국내에는 구기체만 있으므로 오락실마다 기체를 묻거나 기록하지 않는다.
- 설정 페이지에 기체별 값이 두 벌로 보이면 국내 기체에 해당하는 쪽을 읽는다. 일본판은 별도 서버라 동기화 대상이 아니다.
- 페이지에 보이는 나머지 설정도 통째로 함께 저장해 둔다. 나중에 보여 줄 항목을 늘릴 수 있다. 판정 폭 세부 조정(`judgeCritical`/`judgeJustice`/`judgeAttack`) 등은 표에 따로 올리지 않고 이 "나머지" 취급으로 저장만 한다.
- chuni-penguin 어댑터에는 게임 설정 페이지를 읽는 코드가 없다. 파서를 새로 만들어 `chunithm_net` 서비스에 더한다. 저장본: `docs/reference/chunithm-net/arcade_settings.html`.

## 동기화 때의 흐름

동기화 리포트는 조각들의 텍스트만 이어 붙여 보낸다(공개 채널·DM 모두 버튼을 실을 수 없다 — `sync`의 `_render`가 `display.content`만 뽑는다). 그래서 오락실 선택은 버튼이 아니라 말로 받는다.

1. `/동기화`에 `arcade: ArcadeRef`로 오락실을 같이 말했으면("겜플에서 친 거 동기화해 줘") 그대로 아래 이름 확인을 거쳐 방문을 남기고 설정을 저장한다.
2. 말하지 않았고 새 플레이가 있으면, 이 스킬의 조각(order 50)이 "오락실을 말 안 했으면 다음 동기화 때 같이 말하거나 `/오락실 방문`으로 알려 달라"는 안내 문구만 리포트에 한 줄 더한다. 저장은 하지 않는다.
3. 오락실이 정해지면(1번 경로, 또는 나중에 `/오락실 방문`) `arcades` 서비스에 방문(세션 id, 마지막 플레이 날짜)을 남기고, 가장 최근 세션일 때만 CHUNITHM-NET의 현재 설정을 읽어 그 방문에 저장한다.
4. 직전에 저장된 값과 달라진 항목이 있으면 `/오락실 방문` 응답에 한 줄로 짚는다.

- 새 플레이가 없으면 안내 문구를 내지 않는다.
- 두 곳 이상에서 쳤다면 `/오락실 방문`을 여러 번 부른다. 설정은 계정에 하나뿐이므로 마지막 호출에만 저장되고, 나머지는 방문만 남는다.
- 플레이 이력 상세 페이지(`/mobile/record/playlogDetail/`)에는 점포 이름이 없다. 자동으로 알아낼 길이 없으므로 항상 말로 받는다.

## 이름 확인 (`arcades` 서비스와 `ArcadeRef`가 하는 일)

| 입력 | 처리 |
| --- | --- |
| 등록된 이름이나 별칭과 정확히 같음 | 묻지 않고 그 오락실로 처리 |
| 비슷한 후보가 하나 있음 | 모델이 그 오락실이 맞는지, 새 오락실인지 말로 되묻는다. 맞다고 하면 입력한 말을 별칭으로 저장 |
| 비슷한 후보가 여럿 있음 | 후보 목록을 보여 주고 고르게 한다(새 오락실이라는 선택지도 준다) |
| 후보가 없음 | 새 오락실로 등록할지 되묻는다 |

- 예: "광주 게임플라자"가 등록된 상태에서 "겜플"이 들어오면, 광주 게임플라자가 맞는지 새 오락실인지 묻는다. 맞다고 하면 "겜플"이 별칭으로 저장되어 다음부터는 묻지 않는다.
- 후보는 코드가 찾는다(`core/fuzzy.py`): 공백·대소문자·구두점을 뺀 꼴이 같거나 서로 포함하면 후보이고, 아니면 글자 유사도(difflib, 0.5 이상)로 거른다. 이름과 별칭을 한 풀로 보고 오락실 기준으로 중복 없이 비슷한 순서로 최대 3개를 준다. 모델이 줄임말을 풀어 후보를 더할 수도 있다.
- 어느 경우든 저장 전에 플레이어가 확인한다. 모델의 추측만으로 방문도 별칭도 저장하지 않는다. 확인은 말로 받는다(2026-10-21: 멘션 경로의 확인 버튼은 자동 확정이라 확인 구실을 못 한다). 확인을 받은 뒤 `register_arcade`가 저장한다.
- **오락실 목록과 별칭은 봇 전역이다**(2026-10-21 사용자 결정). 서버·플레이어마다 따로 두지 않고, 한 번 저장하면 모든 서버와 DM에서 같은 말이 같은 오락실로 풀린다. 한 별칭은 오락실 하나만 가리키고, 다른 오락실의 이름과 같은 별칭은 저장하지 않는다. 등록한 사람과 시각은 남긴다.
- 오락실을 만드는 길이 구현돼 있지 않았다(2026-10-21 발견: 운영 DB의 `arcades`가 비어 있어 어떤 이름도 못 찾았다). `register_arcade`가 그 길이다.

## 꺼내 보기

- "겜플 세팅 알려 줘"라고 하면 그 오락실에서 마지막으로 저장한 설정과 마지막 플레이 날짜를 보여 준다.
- 지금 계정의 설정(마지막으로 읽은 값)과 다른 항목이 있으면 함께 표시한다. 오락실에 도착해서 무엇을 바꿔야 하는지 바로 알 수 있다.
- 같은 오락실의 지난 설정 변화도 날짜순으로 볼 수 있다.
- 방문 기록과 설정은 기본 비공개다. 기록 공개 설정과 별도로 켠다.
- 세션을 불러올 때(`chunithm.session.viewed`) 그날 저장한 설정을 조각으로 돌려준다.

## 도구

| 함수 | 하는 일 | 인자 | 슬래시 | display | confirm |
| --- | --- | --- | --- | --- | --- |
| `get_settings` | 그 오락실의 마지막 설정과 지금 계정 설정의 차이 | `arcade: ArcadeRef` | `/오락실 설정` | optional | never |
| `history` | 그 오락실의 설정 변화 (표 반환) | `arcade: ArcadeRef` | `/오락실 기록` | 표 | never |
| `record_visit` | 세션에 오락실 방문을 남기고 지금 설정을 저장. 도구 태그 chunithm-linked, cost network | `arcade: ArcadeRef`, 날짜(기본 최근 세션) | `/오락실 방문` | optional | never |
| `register_arcade` | 확인받은 오락실을 등록하고 말한 줄임말을 별칭으로 저장(있으면 별칭만 더함). 서버 공유 데이터라 등록한 사람·시각을 남긴다 | `name`, `alias`(선택) | `/오락실 등록` | optional | never |
| `set_privacy` | 방문 기록과 설정 공개 여부 | `public: bool` | 없음 | optional | never |

`record_visit` 도구와 `on_sync_reported`(동기화 때 이미 오락실을 말한 경우)는 "방문을 남기고, 최근 세션이면 설정을 읽어 저장하는" 같은 내부 함수를 같이 쓴다.
설정 읽기는 가장 최근 세션에만 한다(`records.latest_session`과 비교). 지난 날짜에 오락실을 채우는 경우는 그날 설정을 알 수 없으므로 방문만 남긴다.

## 이벤트

| 방향 | 이름 | 돌려주는 것 |
| --- | --- | --- |
| 받음 | `chunithm.sync.completed` (모으기) | 오락실을 안 말했을 때의 안내 문구 조각. 새 플레이가 없거나 이미 말했으면 없음 |
| 받음 | `chunithm.sync.reported` (알림) | 없음 — `arcade_id`가 있으면 방문을 남기고 설정을 저장한다(`session`이 이전엔 방문만 남겼었다, 구현 결정 참고) |
| 받음 | `chunithm.session.viewed` (모으기) | 그날 저장한 설정 조각(본인이거나 `arcade_privacy`가 공개일 때만) |

## 데이터

| 테이블 | 열 |
| --- | --- |
| `arcade_settings` | 방문 id(`arcades` 서비스), 플레이어, 오락실, 플레이 날짜, 스피드, 필드 월, 판정 A, 판정 B, 가이드음 볼륨, 나머지 설정 전체(JSON), 읽은 시각 |
| `arcade_privacy` | 플레이어, 공개 여부 |

`arcades` 서비스에는 오락실(이름, 등록한 플레이어. `arcades.guild_id` 열은 예전 서버별 구조의 흔적이라 쓰지 않는다), 별칭(별칭, 오락실, 등록한 플레이어. 전역), 방문(플레이어, game, 오락실, 세션 id, 마지막 플레이 날짜)이 있다.

## 유니 지침 (SKILL.md 본문 초안)

- 오락실 이름이 확실하지 않으면 추측해서 저장하지 않는다. `ArcadeRef`가 돌려주는 후보 버튼으로 확정받는다.
- 설정을 물으면 지금 계정 설정과 다른 항목부터 말한다. 다른 항목이 없으면 그대로 쓰면 된다고 말한다.
- 마지막 플레이 날짜를 함께 말한다.

## 테스트

- 저장본 설정 페이지로 파서 테스트.
- 이름 확인의 네 가지 경우와 별칭 저장.
- 여러 곳을 고른 경우 설정이 마지막 곳에만 저장되는지.
- 차이 표시가 바뀐 항목만 나오는지.

## 구현 결정 (2026-10-18)

- chuni-penguin 어댑터에 설정 페이지를 읽는 메서드가 없어, `ChunithmNetAdapterLike` Protocol에 어댑터의 private `_request_as_soup`을 얹어 그대로 썼다(쿠키·인증·에러 훅을 다시 구현하는 중복을 피하려고). `services/chunithm/chunithm_net.py`의 `get_arcade_settings()`가 이 경로를 쓴다.
- `arcade_visits`(공통 `arcades` 서비스)에는 원래 PK가 없었다 — `record_visit()`이 SQLite의 암묵적 rowid를 돌려주도록 바꿔(기존 호출부는 반환값을 안 썼으므로 무해) `arcade_settings.visit_id`가 그 값을 가리키게 했다.
- `session`(7단계 Part 3)의 `on_sync_reported`가 임시로 하던 `arcades.record_visit()` 호출을 이 스킬로 옮겼다 — 두 스킬이 같은 `arcade_id`를 보고 각자 기록하면 방문이 중복된다. 설정 읽기(네트워크 호출)도 방문 기록과 같은 순간에 해야 하므로 한 곳(이 스킬의 `on_sync_reported`)에 묶었다.
- `arcade_settings`에 `play_date` 열을 둬서 `chunithm.session.viewed`가 날짜로 바로 찾을 수 있게 했다 — `session`이 쓰는 `visited_at[:10]` 근사치보다 정확하다(동기화 payload의 `sessions[].play_date`를 그대로 쓴다).
- 판정 폭 세부 조정(`judgeCritical`/`judgeJustice`/`judgeAttack`) 등 이름 안 붙은 항목은 `raw_json`에만 들어가고 표/도구 결과에는 안 나온다(저장만 해 둔다).

## 구현 결정 (2026-10-20)

- 오락실에 묶이지 않은 "지금 계정 설정을 바로 읽기"(`current_settings`)는 `settings` 스킬로 옮겼다. 설정을 실제로 바꾸는 기능(즐겨찾기 곡, 게임 설정 변경)이 생기면서 "CHUNITHM-NET 지금 계정 설정"을 다루는 스킬을 하나로 모으는 게 맞다고 봤다 — 이 스킬은 오락실 방문 이력에 묶인 조회·저장만 남는다. `get_arcade_settings`(서비스 메서드)는 두 스킬이 그대로 같이 쓴다.
- 표시 포맷 도우미(`FIELD_LABELS`, `named_from_settings`, `settings_line`)는 두 스킬이 똑같이 쓰므로 `services/chunithm/arcade_settings.py`로 옮겼다(스킬마다 복사하지 않는다).

## 표로 바꾼 읽기 도구 (16단계 Part 4-4, 2026-10-20)

표 모양·서식은 `docs/plan/2026-10-20_수정.md` §16 Part 4의 4-1·4-2를 따른다. 구현에서 정한 것:
- `history`: 가리키는 것 `arcade.settings_entry` = JSON(오락실 id, 날짜). 칸 날짜·스피드·필드 월·판정 타이밍 A·판정 타이밍 B·가이드음(칸 이름은 `FIELD_LABELS`). 표 요약에 오락실 이름. 서식 없이 기본 출력. 저장된 설정이 없으면 지금처럼 오류다.
