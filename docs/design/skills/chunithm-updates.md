# 유니 스킬: chunithm-updates

Oct 9, 2026 · @astrove

국제판과 일본판 공식 공지와 곡 목록을 주기적으로 확인해, 업데이트가 있는 날 서버 채널에 유니가 알리는 스킬이다. 신곡 이름과 레벨은 곡 목록 비교 결과만 쓴다.

## 개요

```yaml
name: chunithm-updates
description: 츄니즘 국제판·일본판 업데이트 일정과 신곡을 알려 주고, 업데이트 알림을 켜고 끈다.
examples:
  - 다음 업데이트 언제야?
  - 이번에 들어온 신곡 보여 줘
category: 알림
game: chunithm
version: 1
services: [songdb, records, notify, http, players, yuni]
emits: [chunithm.update.detected]
listens: [chunithm.sync.completed]
```

태그 조건은 없다. 알림 설정을 바꾸는 도구만 `admin`이 필요하다.

## 확인하는 곳

| 대상 | 확인하는 곳 | 2026-10-08 확인 결과 |
| --- | --- | --- |
| 일본판 공지 | [공식 뉴스 RSS](https://info-chunithm.sega.jp/feed) | 열림. 제목에 업데이트 날짜가 들어 있고, 업데이트 이틀쯤 전에 게시됨 |
| 일본판 곡 목록 | [공식 music.json](https://chunithm.sega.jp/storage/json/music.json) | 열림. 1,759건 (WORLD'S END 포함) |
| 국제판 공지 | [공식 뉴스 페이지](https://info-chunithm.sega.com/) | RSS 없음. "Details of 10/8 Update" 형식의 글이 전날 올라옴 |
| 국제판 곡 목록 | [공식 music.json](https://chunithm.sega.com/assets/data/music.json), Chunimaru songdb | 둘 다 열림. 공식 1,489건, Chunimaru 1,574곡 |

이 표는 조사 시점의 값이다. 구현할 때 다시 열어 확인한다.

## 동작

1. 두세 시간에 한 번 공지를 확인한다(예약 작업, `catch_up`). 새 글이 있으면 제목에서 업데이트 날짜를 뽑아 저장하고, 그날 오전 10시에 도는 알림 예약을 만든다.
2. 업데이트 당일 오전 10시에 지정 채널에 알린다. 공지 링크와 유니 말투의 짧은 요약을 붙인다.
3. 곡 목록의 전후를 비교해 추가된 곡과 삭제된 곡을 코드가 뽑는다. 신곡 이름과 레벨은 이 비교 결과만 쓴다.
4. 국제판 신곡이면 `songdb`에 새로고침을 요청하고 `chunithm.update.detected`를 낸다.

- **일본판 알림**: 서버 설정으로 켜고 끈다. 국제판에 나중에 들어올 곡의 예고로 쓴다.
- **버전업 감지**: 공지 제목의 버전 이름이 바뀌면 따로 크게 알리고, `admin` 태그를 가진 플레이어에게 CHUNITHM-NET 파서 점검이 필요하다고 DM으로 알린다. 버전업 뒤에는 chuni-penguin 어댑터의 수정을 가져와야 할 수 있다.
- **공지를 놓친 경우**: 공지 없이 곡 목록만 바뀌어도 곡 목록 비교로 알린다.
- **개인 멘션 없음**: 업데이트 알림은 채널 공지 한 건이다. 원하는 사람만 받는 역할 멘션을 선택으로 둔다.
- **켜진 직후**: 새벽 정지 뒤 켜지면 공지와 곡 목록을 바로 한 번 확인한다.

**동기화 리포트 조각 (order 40)**

지난 동기화 뒤에 국제판 신곡이 들어왔다면, 그 중 플레이어의 베스트 프레임 상수대에 맞는 채보를 목록으로 돌려준다. 플레이어의 상수대는 `records`에서 읽는다.

## 도구

| 함수 | 하는 일 | 인자 | 슬래시 | 태그 | display |
| --- | --- | --- | --- | --- | --- |
| `next` | 알려진 다음 업데이트 날짜와 공지 링크 | `region`(국제판/일본판) | `/업데이트 일정` | 없음 | optional |
| `new_songs` | 최근 업데이트의 추가·삭제 곡 | `region`, 날짜(선택) | `/신곡` | 없음 | required |
| `configure` | 알림 채널, 일본판 알림, 역할 멘션 | 각 설정값 | `/업데이트 설정` | `admin` | optional |

## 이벤트

| 방향 | 이름 | 내용 |
| --- | --- | --- |
| 냄 | `chunithm.update.detected` (알림) | 지역, 업데이트 날짜, 추가된 곡, 삭제된 곡, 버전 변경 여부 |
| 받음 | `chunithm.sync.completed` (모으기) | 내 상수대에 맞는 신곡 조각 |

| `updates_song_snapshots` | 지역, 확인 시각, 곡 목록 해시, 추가·삭제 목록 |

## 설정

| 이름 | 범위 | 기본값 |
| --- | --- | --- |
| 알림 채널 | 서버 | 없음(관리자가 지정) |
| 일본판 알림 | 서버 | 켜짐 |
| 역할 멘션 | 서버 | 없음 |
| 알림 시각 | 서버 | 10:00 KST |
| 공지 확인 간격 | 전역 | 3시간 |

## 유니 지침 (SKILL.md 본문 초안)

- 업데이트 날짜와 신곡은 도구 결과로만 말한다. 모르는 날짜는 아직 공지가 없다고 말한다.
- 일본판 소식인지 국제판 소식인지 항상 밝힌다.
- 알림 요약은 두세 문장으로 한다.

## 테스트

- 저장해 둔 RSS와 공지 페이지에서 업데이트 날짜와 버전 이름을 뽑는지.
- 곡 목록 비교의 추가·삭제 계산.
- 같은 공지를 두 번 알리지 않는지.
- 알림 예약이 새벽 정지 시간을 피하는지.

## 미확인 사항

- 국제판 공지 페이지는 RSS가 없어 화면을 파싱한다. 구조가 바뀌면 깨진다. 실패하면 곡 목록 비교만으로 알린다.
- 국제판 공식 곡 목록과 Chunimaru의 건수 차이 원인.
