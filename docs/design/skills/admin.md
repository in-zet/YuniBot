# 유니 스킬: admin

Oct 9, 2026 · @astrove

봇 관리자가 사용량을 보고, 서버별로 스킬을 켜고 끄고, 부여 태그를 붙이고 떼는 스킬이다. `admin` 태그가 없는 사람에게는 이 스킬이 카드와 안내(에이전트 쪽, 우리 코드가 직접 거르는 자리)에 보이지 않는다.

- **슬래시 명령 목록은 예외다.** `/관리` 계열은 디스코드 서버에 등록된 명령이라, 디스코드 클라이언트는 그 서버의 멤버 전원에게 자동완성 목록을 그대로 보여준다 — 우리가 만든 `admin` 태그를 기준으로 디스코드가 특정 멤버에게만 명령을 숨기게 할 방법이 없다(디스코드 자체의 서버 권한으로만 그런 필터링이 가능한데, 그건 우리 태그와 다른 축이라 쓰지 않기로 했다). 그래서 `admin` 태그가 없는 사람도 `/관리` 하위 명령이 목록에 뜨는 걸 볼 수 있다 — 다만 실행하면 `core/executor.py`의 태그 검사가 "모르는 명령이에요"로 막는다(진짜 거부 사유는 숨긴다). 목록에 뜨는 것 자체는 막지 않기로 한 의도적 결정이다.

## 개요

```yaml
name: admin
description: 봇 관리. LLM 사용량과 비용, 서버별 스킬 켜기·끄기, 부여 태그, 스킬 등록 오류를 다룬다.
examples:
  - 이번 달 LLM 비용 얼마야?
  - 이 서버에서 web-qa 꺼 줘
category: 관리
game: common
version: 1
services: [players, settings, registry_snapshot]
tags: [admin]
settings:
  - name: 월 비용 상한
    kind: float
    default: 10.0
    description: 이 서버의 월 LLM 비용 상한(달러 추정)
    scope: guild
  - name: 플레이어 쿨다운
    kind: int
    default: 10
    description: 플레이어별 도구 호출 쿨다운(초)
    scope: guild
```

이 두 설정값은 `set_limits`(확인 버튼 경유) 말고도, 코어의 공통 `/설정 바꾸기` 명령으로도 바로 바꿀 수 있다 — 이 경로는 `admin` 태그만 확인하고 확인 버튼은 없다(다른 스킬의 guild 범위 설정과 동일하게 취급된다).

## 첫 관리자

- `.env`의 `ADMIN_DISCORD_IDS`에 적은 디스코드 계정의 플레이어는 시작할 때 `admin` 태그를 받는다. 이 목록에서 빠지면 다음 시작 때 태그가 떨어진다.
- 그 밖의 관리자는 이 스킬로 붙인다.
- 마지막 관리자의 `admin` 태그는 뗄 수 없다.

## 하는 일

| 함수 | 하는 일 | 슬래시 | display | confirm |
| --- | --- | --- | --- | --- |
| `usage` | 기간별 LLM 호출 수, 토큰, 추정 비용, 검색 횟수. 플레이어별·스킬별로 나눔 | `/관리 사용량` | required | never |
| `skills` | 등록된 스킬, 켜짐 여부, 등록 실패한 스킬과 이유 | `/관리 스킬` | required | never |
| `toggle_skill` | 이 서버에서 스킬 켜기·끄기. `admin`과 `account-link` 자신은 끌 수 없다(끄면 되돌릴 길이 `/관리`나 `/연결` 밖에 없어진다) | `/관리 스킬설정` | optional | always |
| `grant_tag` / `revoke_tag` | 부여 태그와 스킬 태그 붙이기·떼기. 상태 태그는 여기서 바꿀 수 없음 | `/관리 태그부여`, `/관리 태그회수` | optional | always |
| `set_limits` | 월 비용 상한, 플레이어별 쿨다운 | `/관리 상한` | optional | always |

- 모든 응답(위 다섯 함수 + confirm 프롬프트)은 본인에게만 보인다(ephemeral) — 관리 작업 자체가 다른 멤버에게 노출될 이유가 없다.

- 다른 플레이어의 데이터를 바꾸는 유일한 스킬이다. 그래서 바꾸는 도구는 모두 확인 버튼을 거친다.
- 다른 플레이어의 기록, 메모, 메모리, 쿠키를 보거나 바꾸는 도구는 두지 않는다. 관리자도 남의 비공개 데이터는 볼 수 없다.
- 비용 상한의 80%에 닿으면 관리자에게 DM으로 알린다. 상한에 닿으면 코어가 멘션 응답을 고정 문구로 바꾼다.
- 코어와 스킬이 보내는 운영 알림(스킬 등록 실패는 코어가, 버전업에 따른 파서 점검 필요는 chunithm-updates가 보낸다)은 `admin` 태그를 가진 플레이어에게 DM으로 간다.

## 이벤트

내거나 받는 이벤트는 없다.

## 데이터

이 스킬의 테이블은 없다. 사용량 기록과 스킬 상태는 코어에, 태그는 `players`에, 상한은 `settings`에 있다.

## 유니 지침 (SKILL.md 본문 초안)

- 바꾸는 요청은 무엇이 바뀌는지 한 줄로 설명하고 확인 버튼을 낸다.
- 비용은 추정치임을 밝힌다.

## 테스트

- `admin` 태그가 없으면 카드에서 빠지는지, 그리고 슬래시 목록엔 떠도 실행하면 "모르는 명령이에요"로 막히는지.
- 마지막 관리자의 태그를 뗄 수 없는지.
- 상태 태그를 수동으로 바꿀 수 없는지.
